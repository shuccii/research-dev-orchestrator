# Research Dev Orchestrator

研究・機械学習・ソフトウェア開発・就職活動などの複雑なタスクを、根拠、検証、レビュー、承認境界を明確にしながら進めるためのCodexプラグインです。

通常の作業は軽量に扱い、研究・分析・機械学習では、データリーク、再現性、主張と根拠の対応、独立レビューを重視します。

## 主なワークフロー

### `orchestrate-work`

- 複数の作業ストリームを整理し、依存関係と担当範囲を明確化
- 必要な場合だけ並列作業を使い、独立したレビューを記録
- 機械可読なタスクマニフェストと結果を用いて、検証済みの成果だけを統合
- 公開、提出、送信、デプロイなどを承認が必要な操作として扱う

### `research-ml-workflow`

- `research_strict` プロファイルによる研究・分析向けの厳格な検証
- グループ単位の分割、学習データ内での前処理、リーク検査
- 生予測値、反復・シード間のばらつき、不確実性の記録
- 検証に失敗した場合の下流成果物・主張の無効化
- 予測上の関連と因果的解釈の分離

### `research-review-workflow` (v0.4.1)

- 研究監査、修士論文・論文の建設的査読、中間・最終発表の模擬試問、研究計画の評価
- 研究意義・新規性・論理・設計・データ・統計・材料科学・再現性・説明・倫理の10観点を確認
- 主張と根拠の対応、反証・代替説明、指摘の重大性と確度、修正案と解消条件を記録
- Webの一次資料、利用可能なSlack/Notionの原文を読み、取得範囲・知識の不足・未確認を明示
- 材料科学、データ同化、多忠実度、ベイズ最適化について必要な場合だけ専門的な確認を追加
- 模擬試問は回答を待ち、回答内容に応じて追質問する
- 私的な研究室情報は作業領域の `RESEARCH_REVIEW_CONTEXT.md` から参照し、配布物には同梱しない

使用例: 「修士論文を監査して、主張ごとの根拠・代替説明・必要な追加検証を示して」「この中間発表について、一問ずつ質問して回答に応じて追質問して」「研究計画の目的・方法・達成条件・実行可能性を評価して」。

正式な監査レポートの構造検証:

```bash
python3 -B scripts/validate_research_review.py --json review-report.json
```

この検証は宣言された根拠の参照関係や状態の整合性を点検するもので、科学的正しさ・教授と同等の能力・学位合格を保証しません。原データ・実行環境がない文書レビューは、数値的妥当性を未評価として完了できます。実験の実行や科学的結果の統合には、従来の `research_strict` 契約と独立レビューを引き続き使います。教員承認・提出許可は別に扱います。

### `software-delivery-workflow`

- 計画、調査、実装、テスト、レビュー、リリース準備の流れを整理
- 変更範囲、データ境界、テスト計画を明確化
- 秘密情報、認証情報、署名資産、ユーザーデータを成果物やGit履歴から除外

### `job-search-workflow`

- 公式情報を優先した企業・求人情報の確認
- 応募書類とプロフィールの事実整合性・プライバシー確認
- 応募フォームへの入力と最終送信を分離し、送信前の確認を維持

### `lab-policy-workflow`

- ローカル登録された研究室規程を、著者・貢献整理、学会参加計画、要旨・ポスター・口頭発表準備へ適用
- 作業領域の `AGENTS.md` と、必要に応じ `~/.config/research-dev-orchestrator/lab-policies.md` から適用対象を解決
- 規程本文・原本PDF・個人の参照パスはプラグインに同梱せず、研究室ごとの適用範囲を維持
- 教員確認・発表練習・承認状態と、ユーザーの提出・送信許可を区別

この機能はローカル設定を参照するワークフローであり、教員承認を取得・代行する機能ではありません。他の環境で使う場合は、その環境に適切な規程と参照先を登録してください。

## ディレクトリ構成

```text
.
├── .codex-plugin/plugin.json       # プラグインマニフェスト
├── skills/                         # Codexが利用するワークフロー
├── assets/                         # 検証用JSONスキーマとポリシー
├── scripts/                        # マニフェスト・結果・研究契約の検証スクリプト
├── tests/                          # 自動テストとテストフィクスチャ
├── benchmarks/                     # 評価プロトコルとハーネス
├── baseline/                       # 比較用の基準記録
└── benchmark-results/              # 評価結果とリリース記録
```

## 取得と検証

```bash
git clone https://github.com/shuccii/research-dev-orchestrator.git
cd research-dev-orchestrator
python3 scripts/run_checks.py
```

現行リポジトリの検証スクリプトは、契約、マニフェスト、研究向け検証、評価ハーネスのテストを実行します。テストが成功しても、個別の研究結果や科学的主張の妥当性が自動的に保証されるわけではありません。

Codexプラグインとして利用する場合は、`.codex-plugin/plugin.json` をエントリポイントとして、利用中のCodex CLIまたはアプリのプラグイン管理機能からこのリポジトリを登録してください。CLIの具体的なコマンドは、利用するCodexのバージョンに合わせて確認してください。

## 研究タスクでの基本方針

研究・機械学習では、次の順序で確認します。

1. 研究質問、目的変数、独立単位、許可されたデータソースを定義する
2. 分割単位と評価指標を固定する
3. 前処理・特徴量選択・補完・リサンプリングを学習データ内で実行する
4. 生の予測値、設定、シード、ログ、生成物を保存する
5. 独立レビューでリーク、指標、解釈、再現性を確認する
6. 根拠の範囲を超える因果・一般化・性能主張を避ける

未実行の計算、取得できないデータ、検証待ちの値は、結果として扱わず制約として明示します。

## 公開時の注意

- 認証情報、APIキー、秘密鍵、個人情報、ユーザーデータをコミットしないでください。
- 公開リポジトリではコミット履歴も閲覧できるため、削除したファイルに秘密情報が残っていないか確認してください。
- `baseline/` と `benchmark-results/` には評価記録が含まれます。公開してよい内容か確認したうえで利用してください。
- このリポジトリにはライセンスを設定していません。改変・再配布・商用利用の条件は、権利者に確認してください。

## バージョン

v0.4.1 は、ローカル設定で指定した研究の現状・既知の弱点・過去の指導の必読、指摘の改善追跡、研究室の指針と専門知識の参照を追加します。私的資料は配布物へ含めず、取得できない場合は文脈が不完全と明示します。既存の研究・レビューJSON契約は変更しません。

現在のプラグインマニフェストに記載されたバージョンは `0.4.1` です。

v0.4.0 は研究レビュー用の契約を追加します。既存の v0.3.0 タスク・研究契約の形式と検証条件は維持しています。公開一次資料の確認範囲は `skills/research-review-workflow/references/public-sources.md` に記載しています。

実際のサブエージェント識別子を保持できるよう、結果契約の worker/reviewer/observer ID は従来のIDに加えて `/root/reviewer` 形式も受け付けます。タスクIDと成果物パスの制限、独立性のチェックは維持します。
