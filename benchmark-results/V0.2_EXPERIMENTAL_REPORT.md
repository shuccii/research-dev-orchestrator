# Research Dev Orchestrator v0.2 experimental report

## Decision

Do not release v0.2.0 from the current experimental branch. Keep the installed v0.1.0 active. The implementation and deterministic infrastructure are complete enough for further experimentation, but the public release gate is not met: the full six-case paired evaluation is incomplete, and the independent-module smoke run fails the mandatory independent-review criterion in the current `codex exec` environment.

Consequently, `.codex-plugin/plugin.json` remains at 0.1.0, no v0.2 tag or cachebuster was created, the personal marketplace was not changed, and the plugin was not reinstalled.

## Implemented changes

- Dependency-free JSON Schema subset validation with fail-closed unknown keyword handling.
- v0.2 task-result contract, structured checks, legacy archive-only reading, timestamps, identity, blocked reasons, approval state, artifact safety, and independent semantic-review checks.
- Optional task manifest with budgets, DAG checks, normalized POSIX write scopes, cycle/missing-dependency detection, path-element conflict detection, risk routing, approval-node semantics, and dependency-ready queries.
- Host-observed metrics from JSON events and monotonic time, explicit unavailable fields, process timeouts, retry bounds, token-budget handling, frozen pack/case/evaluator hashes, session isolation, adjudication binding, and holdout gating.
- Public synthetic cases, planted defect IDs, fixed critical/noncritical rubrics, two holdouts, and separate gitignored private-fixture routing.
- Reviewer-input and direct-path guidance. Small mechanical operations bypass manifest/delegation/review overhead. Semantic risks, implementation changes, research conclusions, external facts, security, and job claims remain review-required.
- Fail-closed collaboration evidence: started/completed lifecycle aggregation, concrete receiver identities, unbound-wait rejection, one coherent manifest for both independent implementation results, and reviewer identity bound to a host-observed agent ID.

The original lightweight nature is retained: this is still a Codex skill pack with schemas and local scripts, not a scheduler, service, MCP server, or custom agent runtime.

## Verification results

- Deterministic suite: 40 tests passed with `python3 -B scripts/run_checks.py`.
- Frozen v0.1.0 tag and installed-cache hashes: matched all seven original files.
- All four skills: passed the bundled skill validator in an isolated validation environment.
- Plugin structure: passed the bundled plugin validator.
- Independent code review: no P0 remained after remediation; identified P1 grading, telemetry, approval, session, holdout, and evidence-composition gaps were converted into regression tests.

## Public evaluation status

The preliminary v0.1 record contains one complete six-case pilot plus one earlier formatting smoke run; it is explicitly not the requested three-repeat final baseline. Final claims use only fresh paired sessions.

The corrected formatting diagnostic completed three pairs. All value, formatting, newline, and zero-collaboration checks passed. The v0.2/v0.1 active-time ratio median was 0.2589. v0.2 used fewer input and output tokens in all three pairs.

The first full post-correction primary attempt reproduced that formatting improvement, but the v0.2 independent-module task timed out at 300 seconds on all three permitted attempts. A later v0.2-only smoke completed in 265.44 seconds with 521,378 input and 12,780 output tokens. It passed implementation, test, manifest, and noncritical checks, but failed independent review because the CLI exposed no collaboration event, spawn call, or agent identity. This is a mandatory critical failure.

Therefore:

- Full six-case public quality: not established.
- Six planted defect IDs and false-positive comparison: not finally adjudicated.
- Overall paired active-time median: unavailable.
- Per-case 1.15 cap: not established for all cases.
- Holdout: correctly not run because primary did not pass.
- Private set: not configured; it is not required for a future public release.

## Review omission boundary

Automatic omission is restricted to the closed machine modes in `verification-policy.json`: formatting, file movement, lint execution, unit-test execution, and rendering from already reviewed metrics. Manifest risk tags and actual check provenance are cross-checked. Unit tests do not waive review of code intent. Any semantic mode or relevant risk tag remains fail-closed and requires a distinct reviewer.

## Metrics and unavailable fields

Elapsed/active time, tokens exposed by `turn.completed`, event/tool counts, observed collaboration/spawn calls, retries, status, and artifact grades were collected by the host. Approval wait is zero only because the benchmark is noninteractive and has no human approval channel.

LLM request count, total subagent count, reviewer count, observed model identity, billing cost, and exact approval-wait decomposition were not exposed and remain `null` with reasons. Turn or tool counts were not substituted for LLM calls. `max_llm_calls` therefore blocks before execution with `budget_unobservable`.

## Next candidates

For a later experimental revision, first obtain a `codex exec` adapter that exposes successful worker/reviewer spawn identity and completion evidence, or revise the common evaluation transport without weakening the independent-review requirement. Only then rerun the full paired public set and holdout. Resume, evidence caching, adaptive concurrency, a custom scheduler, MCP/service observability, and adopted model hierarchy remain v0.3-or-later work. Model hierarchy was not measured because the environment did not expose verifiable per-agent model identity and the primary gate failed.
