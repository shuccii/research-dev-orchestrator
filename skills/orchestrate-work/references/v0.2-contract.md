# v0.2 contract reference

The plugin root contains the machine-readable contract and dependency-free tools:

- `assets/task-manifest.schema.json`: manifest structure and closed enumerations.
- `assets/task-result.schema.json`: result and verification structure.
- `scripts/validate_task_manifest.py`: dependency, path, risk-routing, readiness, and conflict checks.
- `scripts/validate_task_result.py`: schema and cross-field validation with optional legacy archive reading.

From the plugin root, validate with:

```bash
python3 scripts/validate_task_manifest.py --json runs/<run-id>/tasks.json
python3 scripts/validate_task_result.py --json --manifest runs/<run-id>/tasks.json runs/<run-id>/*/result.json
```

The result validator returns exit code 0 for valid inputs, 1 for contract failures, and 2 for invocation or internal validation errors. `--legacy-read-only` makes a versionless v0.1 result archive-readable; it never makes that result eligible for v0.2 integration.

Artifact paths are normalized paths relative to the directory containing that task's `result.json`. Absolute paths, parent traversal, and symbolic links are rejected before integration.

`ready_tasks` means dependency-ready. Inspect `write_conflicts` before choosing a parallel subset. Two tasks may declare the same write scope when dependency ordering makes their execution sequential.

The machine-only verification modes are limited to formatting, file movement, lint execution, unit-test execution, and rendering from already reviewed metrics. Any semantic risk tag requires `semantic_review_required`, regardless of the requested check command.
