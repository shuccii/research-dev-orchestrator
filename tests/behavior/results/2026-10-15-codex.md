# Codex workflow behavior checks — 2026-10-15

Compared the original plugin (`e6340a4`, v0.4.1) with the v0.5.0 port of the generic workflow controls from mi-orchestrator `8235d7f`.

## What was checked

A fresh worker per version performed the four input-only cases in `../cases.json` using isolated fixture copies and standard-library Python. An independent reviewer inspected the artifacts, actual command records and `../rubric.md`. Each worker handled all four cases. This is a qualitative smoke test, not a controlled performance benchmark; exact model IDs, matched token usage and wall-time measurements are unavailable.

| Case | Observed behavior in the original and first candidate runs |
| --- | --- |
| Invalid log-fit inputs | Both located zero/missing conductivity, preserved the source and avoided a silently validated fit. Original saved a clearly provisional disclosed subset fit; candidate blocked the all-row fit with null coefficients. Both responses retained scientific limitations. |
| Unauthorized plot changes | Both rejected thinning and extra style changes. Candidate explicitly separated requirements review from mandatory integrity checks. |
| Missing dependency | Both proposed prerequisite repair before resuming, without installing or re-dispatching unchanged work in this decision-only exercise. |
| Small Notebook construction | Both produced a one-cell Notebook and actually checked JSON/cell count/AST, without delegation or a kernel-execution claim. |

Neither first-run trace established that the consuming worker reopened the saved numerical JSON before composing its numerical report. The reviewer marked that item unassessed/partial for both versions; later parent inspection is not counted as prior worker behavior. The candidate skill was refined to make the numerical handoff an explicit artifact/key/readback-command/value/scope table. The original traces and findings were retained rather than rewritten.

The paired smoke exercises do not demonstrate a general capability gain, lower failure rate, lower latency or lower cost. Differences in report structure are not automatically improvements in substantive correctness. A separate Claude-side comparison also reported no demonstrated substantive performance gain, so that claim is not imported into this port.

## Coverage limits

These cases do not behaviorally prove live asynchronous recovery, the three-repair stop rule, two-round review budgets, newly discovered serious defects on re-review, hard compute budgets, full strict-research execution or external approval operations. Those procedures were inspected in independent source review, and existing contracts remain in force. All 95 existing automated tests passed; all seven skill-format checks and local reference checks passed. Existing schemas and runtime validators were unchanged.

This is a targeted follow-up sample after a known evidence gap, not an additional matched baseline comparison.
